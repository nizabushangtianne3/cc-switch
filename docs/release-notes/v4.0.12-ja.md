# CC Switch v4.0.12

### 4.0 安定ラインの 7 回目の修正リリース

このリリースは、シングルキーの使用量帰属とデータベース v21 の移行順序を修正し、schema 21 より前に作成されたデータベースで起動が失敗する問題を防ぎます。旧データからキーを推定したり、使用量を遡って入力したりしません。更新された行は未帰属のままです。

## 修正

- **シングルキーのプロバイダーにキーメタデータがなかった問題。** 有効な API キーを 1 つ保存すると、`meta.apiKeys` と `meta.apiKeyStrategy` も保存します。既存のシングルキープロバイダーは、キー単位の使用量統計に参加するために、再度保存するかキーを再追加する必要があります。
- **データベース v21 の移行順序が誤っていた問題。** v20 → v21 移行では、インデックスを作成する前に `proxy_request_logs.api_key_id` を追加し、日次ロールアップを新しいキー次元で再構築します。古いロールアップ行の `api_key_id` は空で、キー帰属がないことを示します。

## アップグレードに関する注意

- データベース schema バージョンは 21 のままです。
- このリリースは旧データからキーを推定したり、使用量を遡って入力したりしません。
