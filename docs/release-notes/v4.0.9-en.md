# CC Switch v4.0.9

### The fork's signed Android release

This release brings CC Switch to Android with officially signed arm64 and armv7 APKs. The mobile app reuses Aggregation mode, so the local proxy continues to handle unified routing and key-pool forwarding. Usage statistics also gain a key dimension that can be combined with app, provider and model filters. The release workflow verifies every Android signature before upload and generates the desktop updater manifest with a fork-specific Tauri signing key. Desktop builds still cover the Windows MSI, Linux AppImage / deb / rpm and macOS Universal DMG. Because this fork has no code-signing certificate, desktop packages remain unsigned.

---

## New

**Signed Android installers.** Release Assets include `arm64-v8a` and `armeabi-v7a` APKs for 64-bit and 32-bit Android devices. The APKs are signed with the release keystore stored in GitHub Secrets, with `versionCode` `4000009`.

**Key-level usage statistics.** Proxy requests store a SHA-256 fingerprint of the selected key, never the raw key. The Usage page adds a Keys tab with app, provider, model and key filters for requests, tokens, cost, success rate, latency and speed; current keys appear as `Key #index · mask`, while deleted keys show the first eight fingerprint characters.

## Improved

**Unified routing on Android.** The Android app reuses Aggregation mode's local proxy. Providers, model mappings and multi-key routing use the same backend implementation as the desktop app, without per-agent proxy adapters.

**Release signature checks.** After building Android, GitHub Actions verifies each APK with `apksigner verify`, generates signed desktop updater artifacts and `latest.json`, and fails if any signing secret or platform signature is missing.

## Fixed

**Android cross-builds from Windows.** The old `build.rs` used host cfg attributes when adding Windows manifest linker flags, so compiling Android from Windows passed `/MANIFEST` arguments to Android Clang. It now reads `CARGO_CFG_TARGET_OS`.

## Upgrade Notes

**The database schema upgrades to 21**, adding the `api_key_id` fingerprint dimension to detail logs and 30-day rollups. The upgrade creates a migration backup automatically; old rows cannot reveal which key was used and appear as unidentified or are omitted from key statistics.
