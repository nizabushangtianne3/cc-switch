# CC Switch v4.0.18

### The ninth maintenance release on the 4.0 line

This release turns the DeepSeek DSML cleanup into a unified output rule: whenever a Chat upstream leaks DSML tool-call scaffolding, every model goes through the same parse, strip and recover path. The reasoning-continuation guard also no longer requires a DeepSeek model id.

## Changed

- **Unified inline tool-call rule.** Detection is driven by the response text instead of the model or provider name. The v4.1 spaced form, standard DSML blocks, ASCII-pipe fallback and `<｜｜DSML｜｜:ToolName>` form all share one path: complete blocks become real tool calls, while stray markers and parser fragments such as `_INVOKE_PREFIX = '` are removed.
- **Reasoning-continuation guard for every model.** When a response has already produced an unfinished reasoning stream, long fragments that an upstream misroutes into `content` stay in the reasoning channel instead of appearing as a visible message.

## Upgrade notes

- No database schema change (still 21).
- No configuration change is needed; start a new turn after upgrading.
- The fork's multi-key pools, key-level usage statistics and single-key persistence behave as before.
