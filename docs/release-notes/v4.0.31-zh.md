# CC Switch v4.0.31

本版本补上「上游拒绝不支持的参数」的最后一种形态，并修正剥参的作用层。

## 修复

### 流内 error 事件也走剥参重试

Anthropic 系网关拒绝转换注入的参数（如 `thinking`）时，回的是 HTTP 200 + 流里第一条 `event: error`——400 整流器抓不到这种形态，客户端见到流内报错就中止会话，后续同会话请求全废。现在流式响应交给客户端之前会先窥探第一条 SSE 块：是 error 事件就回到重试循环剥参重试（解析不出参数时错误原样 surfaced，客户端至少拿到完整错误），不是 error 事件则读过的字节原样接回，客户端看到的流和没有经过这层一样。

### 剥参改到出站体

`thinking` 这类参数是代理转换器注入的（来自 `reasoning.effort`）、`max_tokens` 是默认值，在客户端发的请求体里根本不存在——原来的整流和能力缓存都在请求体上剥，对转换路径永远空转。改成在出站体（转换之后）剥，能力缓存的预剥和整流重试共用这一层，调用方那层重复逻辑删除。
