# CC Switch v4.0.31

本リリースは「上流が非対応パラメータを拒否する」最後の形態をカバーし、剥離の対象層を修正します。

## 修正

### スト内 error イベントでも剥離リトライ

Anthropic 系ゲートウェイが変換時に注入したパラメータ（thinking など）を拒否するときの応答は HTTP 200 + ストリーム先頭の `event: error` で、400 整流器には見えず、クライアントはスト内エラーでセッションを中断し、以降同セッションのリクエストは全て失敗していました。ストリーミング応答をクライアントに渡す前に先頭の SSE ブロックを覗き見るようにしました。error イベントなら剥離リトライのループに戻し（パラメータ名が解析できない場合はエラーをそのまま返すので、少なくとも完全なエラーは得られます）、error でなければ読み済みのバイトをそのまま戻し、クライアントの見るストリームは事前と変わりません。

### 剥離を送信ボディに移動

thinking などのパラメータはプロキシの変換器が注入する（reasoning.effort 由来）もので、max_tokens はデフォルト値です。クライアントが送ったリクエストボディには存在しないため、整流も能力キャッシュも変換経路では空転していました。送信ボディ（変換後）で剥離するようにし、能力キャッシュの事前剥離と整流リトライで共用、呼び出し側の重複処理は削除しました。
