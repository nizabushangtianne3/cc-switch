# CC Switch v4.0.12

### The seventh fix release for the 4.0 stable line

This release fixes single-key usage attribution and database v21 upgrade ordering, preventing startup failures when upgrading a database created before schema 21. It does not infer keys or backfill usage from old data; upgraded rows remain unattributed.

## Fixed

- **Single-key providers lacked key metadata.** Saving one valid API key now also writes `meta.apiKeys` and `meta.apiKeyStrategy`. Existing single-key providers must be saved again or re-added before they participate in key-level usage statistics.
- **Database v21 upgrade order was wrong.** The v20 → v21 migration now adds `proxy_request_logs.api_key_id` before creating its index and rebuilds daily rollups with the new key dimension. Old rollup rows have an empty `api_key_id`, meaning they had no key attribution.

## Upgrade notes

- No further database schema version increase; the schema remains 21.
- This release does not infer keys or backfill usage from old data.
