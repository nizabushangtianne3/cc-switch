# CC Switch v4.0.12

### 4.0 稳定线的第 7 个修复版本

本版修复单 Key 供应商的用量归属，并调整数据库 v21 升级顺序，避免老库启动时因先创建 `api_key_id` 索引而失败。没有从旧数据反推 Key 或回填用量；升级前的老数据会保留为未归属状态。

## 修复

- **单 Key 供应商缺少 Key 元数据。** 供应商表单保存一个有效 API Key 时，现在也会保存 `meta.apiKeys` 和 `meta.apiKeyStrategy`。已有的单 Key 供应商需要重新保存或重新添加 Key 后才会参与 Key 级用量统计。
- **v21 老库升级顺序错误。** v20 → v21 迁移现在先补 `proxy_request_logs.api_key_id`，再创建索引；`usage_daily_rollups` 会按新主键维度重建。老汇总行的 `api_key_id` 为空，表示当时没有 Key 归属。

## 升级说明

- 无数据库 schema 版本进一步增加，仍是 21。
- 本版不做旧数据 Key 反推或用量回填；旧数据保持未归属状态。
