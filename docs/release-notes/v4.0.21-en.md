# CC Switch v4.0.21

This release merges upstream v4.0.16 through v4.0.20 and lands the fork's proxy core overhaul. Upstream adds Oh My Pi as the thirteenth managed app (providers, MCP, Skills, prompts and sessions), splits the Apps page into installed and not-installed sections with drag reordering, makes official Kimi cards editable and removable, and adds browser login for managed ChatGPT accounts, along with clearer balance and failed-quota wording, Turkish translations and refreshed model presets. The fork keeps multi-key pools, key-level usage statistics and single-key persistence unchanged, and rewrites the proxy hot path so request bodies, response bodies and SSE events are moved and pooled instead of copied byte by byte. See the [v4.0 release notes](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-en.md) for the full upstream history.

---

## Added

**Oh My Pi (`omp`) joins as the thirteenth app.** Providers are edited as text in `models.yml`, with only CC Switch's own entry rewritten and anchored, tagged or flow-style entries refused; MCP goes to `mcp.json`, Skills follow Pi, the global prompt goes to `AGENTS.md`, and sessions can be browsed. The Apps page installs and updates it through the official installer and can uninstall it.

**Official Kimi cards can be edited and removed.** Editing keeps the connection managed by the Auth Center and fetches the account's own catalog; removal drops the card from `config.toml` while the credential stays, and "Add" restores it.

**Managed ChatGPT accounts can sign in through the browser.** Authorization code plus PKCE with a loopback callback sits next to device-code login in the Auth Center and the Codex form, reauthentication included.

## Changed

**The proxy hot path no longer copies byte by byte.** Raw request bodies are stored without `Arc` and written with the head as one vectored request; large response bodies are not copied; the keep-alive pool retains connections across concurrent requests; SSE blocks are scanned by one SIMD-friendly scanner and converted events are assembled in a single pass; Codex, Anthropic and Gemini event construction share one set of helpers.

**Database reads and writes are cheaper.** Provider, failover queue and proxy request configuration reads are cached, the effective provider and queue resolve in one query, the main database runs in WAL mode with NORMAL sync, usage writes go through one canonical logger, and its event buffer is consumed without an async lock.

**The usage page follows upstream.** The app filter lists only apps shown on the Apps page, time comes first in the range bar, and the metric strip shares one panel with the trend chart / heatmap; the fork's Key filter and display/pricing settings tab are unchanged.

## Fixed

- **Conversion paths are covered end to end after the rewrite.** Codex, Claude and Gemini streaming, error mapping, failover switching and transform fallbacks all have tests; repeated headers keep their wire order, non-streaming usage is parsed off the response path, and content codings are split without touching the heap.
- **The API Key dimension migration is restored.** v20 to v21 now performs both upstream's Antigravity switch and the fork's `proxy_request_logs.api_key_id` dimension, so key-level usage statistics survive an upgrade from an older database.
- **MCode and Kimi lists stop writing when nothing changed.** Providers are written back only when the native config really changed; Kimi still normalizes identity before writing.

### Upgrade Notes

- **Schema upgraded to 23** (adds `enabled_omp` for Oh My Pi).
- The fork's multi-key pools, key-level usage statistics and single-key persistence are unchanged.
- Upstream presets were refreshed: `moonshotai/kimi-k3` is gone from NVIDIA and Kimi K2.6 replaces it, so the reasoning tiers are no longer declared there.
