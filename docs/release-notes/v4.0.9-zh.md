# CC Switch v4.0.9

### fork 的 Android 正式版

这个版本把 CC Switch 带到 Android：新增 arm64 和 armv7 两个正式签名 APK，手机端复用现有聚合模式，由本地代理继续完成统一路由和 Key 池转发。用量统计也新增 Key 维度，可以按应用、供应商、模型和 Key 组合查看。发布流程会在上传前验签 Android 包，并用 fork 专用 Tauri 更新密钥生成桌面更新清单；密钥缺失时直接失败。桌面端仍提供 Windows MSI、Linux AppImage / deb / rpm 和 macOS Universal DMG。由于 fork 仓库没有代码签名证书，桌面安装包保持未签名。

---

## 新增

**Android 正式安装包。** Release Assets 提供 `arm64-v8a` 和 `armeabi-v7a` 两个 APK，分别适配 64 位和 32 位 Android 设备。APK 使用 GitHub Secrets 中的 release keystore 签名，`versionCode` 为 `4000009`。

**Key 级用量统计。** 代理请求会记录所选 Key 的 SHA-256 指纹，不保存明文 Key。Usage 页新增 Key 页签，可以组合应用、供应商、模型和 Key 筛选，查看请求数、Token、成本、成功率、延迟和速度；当前 Key 显示为 `Key #序号 · 掩码`，已删除 Key 显示指纹前 8 位。

## 改进

**手机端统一路由。** Android 版复用聚合模式的本地代理能力，供应商、模型映射和多 Key 路由逻辑与桌面端保持同一套后端实现，不需要为每种 Agent 单独做代理适配。

**发布验签。** GitHub Actions 构建 Android 后会用 `apksigner verify` 校验每个 APK，并为 Windows、Linux 和 macOS 生成签名更新产物与 `latest.json`；任一签名 Secret 或平台签名缺失时提前失败。

## 修复

**Windows 上交叉编译 Android 失败。** 旧的 `build.rs` 用宿主机 cfg 判断是否注入 Windows manifest 参数，导致在 Windows 上编译 Android 时把 `/MANIFEST` 传给 Android Clang。现在改为读取 `CARGO_CFG_TARGET_OS`。

## 升级说明

**数据库结构升级到 21**，为明细日志和 30 天后的日汇总增加 `api_key_id` 指纹维度。升级会自动创建迁移备份；旧数据无法反推当时使用的 Key，Key 统计中会归为未识别或不显示。
