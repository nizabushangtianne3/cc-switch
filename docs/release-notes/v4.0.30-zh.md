# CC Switch v4.0.30

本版本修复个别上游网关按客户端形态整条拒绝请求导致会话被打断的问题。

## 修复

### 上游网关按客户端形态拒掉请求时，代理自动改走标准客户端重发

个别网关（如 AMD 开发者站点的 Azure 应用网关）会按 TLS/HTTP 客户端形态整条拒绝请求：返回一个不带任何有用信息的 HTML 400，而同一份请求字节换一个标准客户端就能通过（实测：同一台机器上 curl 成功、我们自己的标准客户端成功，只有代理的两条出站客户端被拒）。客户端见到 400 就中止会话，后续同会话请求也全部失败。

现在两条出站路径都有兜底：保持原始 header 大小写的 raw 路径、OpenAI 系格式（chat/completions、responses、Codex 原生）走的 reqwest 池化路径，拿到「网关级拒绝」（4xx/5xx 且响应体不是 JSON——真正的 API 错误都是 JSON，不会误触发）时，自动把同一份字节经标准客户端重发一次。客户端拿到的是重发后的响应，会话不中断。配置了代理时不会绕过代理重试。
