# CC Switch v4.0.31

This release covers the last remaining form of "upstream rejected an unsupported parameter" and moves parameter stripping to the layer where it can actually work.

## Fixes

### In-stream error events now also trigger strip-and-retry

Anthropic-style gateways reject converter-injected parameters (such as `thinking`) with HTTP 200 plus a first `event: error` in the stream, a form the 400 rectifier could not see, so the client aborted the session on a mid-stream error and every later request in that session failed. Streaming responses are now primed before reaching the client: if the first SSE block is an error event it returns to the retry loop for strip-and-retry (errors that name no parameter surface intact, so the client at least gets the full error); otherwise the bytes already read are replayed unchanged and the client sees exactly the same stream as before.

### Stripping moved to the outbound body

Parameters like `thinking` are injected by the proxy's converter (from `reasoning.effort`), and `max_tokens` is a default, so they never existed in the request body the client sent, making both the rectifier and the capability cache no-ops on converted paths. Stripping now happens on the outbound body after conversion, shared by the capability-cache pre-strip and the rectifier retry; the redundant caller-side pass is removed.
