# CC Switch v4.0.21

本版本把上游 v4.0.16 至 v4.0.20 的更新合进 fork，并落地 fork 自己的代理核心重构。上游带来第 13 个受管理应用 Oh My Pi（供应商、MCP、Skills、提示词和会话都能管）、「应用」页按已安装 / 未安装分组且可拖动排序、Kimi 官方卡片可以编辑模型并从 Kimi Code 移除、托管的 ChatGPT 账号可以用浏览器登录，还有余额与「额度查询失败」的措辞、土耳其语翻译和全部预设的模型 ID 刷新。fork 这一侧保留多 Key 池、按 Key 的用量统计和单 Key 持久化，重写代理热点路径：请求体、响应体和 SSE 事件改为移动与池化，不再逐字节拷贝。4.0 完整的更新内容请见 [v4.0 发布说明](https://github.com/farion1231/cc-switch/blob/main/docs/release-notes/v4.0.4-zh.md)。

---

## 新增

**Oh My Pi（`omp`）作为第 13 个应用接入。** 供应商按文本写在 `models.yml` 里，只重写 CC Switch 自己那一条，带锚点、标签或流水样式的条目会拒绝写入；MCP 写 `mcp.json`，Skills 跟随 Pi，全局提示词写 `AGENTS.md`，会话可以浏览。「应用」页用官方安装器安装和升级，能卸载。

**Kimi 官方卡片可以编辑和移除。** 编辑仍由授权中心托管连接，会按账号自己的目录拉模型；移除只从 `config.toml` 删卡片，凭据保留，「添加」可以再拿回来。

**托管的 ChatGPT 账号可以用浏览器登录。** 授权码 + PKCE + 本地回调查端口的登录方式和设备码登录并列放在授权中心和 Codex 表单里，重新登录同样支持。

## 改进

**代理热点路径不再逐字节拷贝。** 原始请求体不再包一层 `Arc`，请求头与请求体合成一次向量写；大响应体不再复制；keep-alive 连接池跨并发请求保留连接；SSE 块用同一个 SIMD 扫描器切分，转换后的事件一次装配完成；Codex、Anthropic、Gemini 三家的事件构造走同一套帮手。

**数据库读取与写入更快。** 供应商、故障转移队列和代理请求配置改为缓存，生效供应商和队列一次查询解析；主库开 WAL、同步级别降到 NORMAL；用量写日志收敛到一个实现，事件缓冲消费不再持异步锁。

**用量页与上游对齐。** 「应用」筛选只列「应用」页设为显示的应用，范围栏时间排第一，指标条与趋势图 / 热力图合并在概览面板里；Key 筛选、显示与定价设置页签保持 fork 原有行为。

## 修复

- **代理重构后的转换补齐端到端测试。** Codex、Claude、Gemini 的流式响应、错误映射、故障转移切换和转换回退都有覆盖用例；重复请求头保持线上顺序，非流式用量在响应路径之外解析，内容编码切分不碰堆。
- **升级时补齐 API Key 维度迁移。** v20 → v21 现在同时完成上游的 Antigravity 开关和 fork 的 `proxy_request_logs.api_key_id` 维度，老库升级后按 Key 的用量统计不会失效。
- **MCode / Kimi 列表不再无谓写库。** 只有原生配置里真的改了才回写，Kimi 仍按上游逻辑做身份归一化后回写。

### 升级说明

- **数据库结构升级到 23**（新增 Oh My Pi 的 `enabled_omp`）。
- fork 的多 Key 池、按 Key 的用量统计、单 Key 持久化行为不变。
- 上游 v4.0.16–v4.0.20 的预设已刷新：NVIDIA 上的 `moonshotai/kimi-k3` 已下线，改为现存的 Kimi K2.6，并相应不再声明思考档位。
