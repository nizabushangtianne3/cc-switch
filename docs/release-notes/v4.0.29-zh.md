# CC Switch v4.0.29

本版本合并了上游的 GitHub Copilot CLI 支持，并修复了一个影响第三方模型使用的大问题：上游拒绝请求里不支持的参数时，整个会话不再被废掉。

---

## 新增

### GitHub Copilot CLI 作为受管应用接入

Copilot CLI（`copilot`）现在和 Claude Code、Codex 一样是 CC Switch 里的受管应用：

- **官方卡**：「打开终端」时带上授权中心绑定的 GitHub 账号 Token，并按卡上设置带上模型和推理档位；添加卡片不写任何文件。
- **自带模型（BYOK）卡**：地址、Key 和模型只经 `COPILOT_PROVIDER_*` 环境变量交给这一次 `copilot` 进程，密钥不落盘；卡上同时有地址和凭据时才算隔离启动。
- **同步**：MCP 服务器（`mcp-config.json`）、Skills 和说明文件跟随卡的启用范围同步到 Copilot CLI。
- **会话**：列出、搜索和继续 Copilot CLI 的会话；从会话日志导入用量。
- **深链接**：支持从 `ccswitch://` 链接导入 Copilot 供应商。
- **侧栏与卸载**：应用列表、卡片角标、连通检测、卸载清单都已覆盖 Copilot CLI。

## 修复

### 上游拒绝不支持的参数时，会话不再整个废掉

第三方模型对请求参数的支持度参差（`reasoning_effort`、`tool_choice`、`temperature`……）。以前客户端按通用形态发过去的请求会被上游整条 400 拒掉，客户端见到 400 就中止会话，同一会话后续请求也全部失败。现在改由代理层消化：

- **去参重试**：收到点名的 400 后，从请求体删掉被点名的参数，对同一家重试一次——客户端拿到的是 200，会话不中断。只认明确点名参数的措辞（OpenAI 的 `error.param`、`Unsupported parameter: 'x'`、`does not support the 'x' parameter`、`Unknown field x`、中文「不支持的参数」等），解析不到就放弃，不猜；`model`/`messages`/`stream`/`input` 等核心键永不被剥。
- **能力缓存**：「这家这个模型不支持这些参数」记入内存缓存并持久化到 settings，重启后第一次请求就生效；后续请求（同会话或新会话）发送前直接剥掉，零报错。
- 缓存在「设置」里可见可管，删掉后恢复按通用形态发送。

## 优化

- **Copilot / xAI 认证**：管理器的外层 `RwLock` 去掉（内部本就有细粒度锁），读锁不再跨上游网络往返，登录、删号不再被用量查询堵住。
- **设置页懒加载**：进设置只加载默认的「通用」分区，切到哪片才拉哪片的代码；每块懒加载自带加载态，同一分区里的静态内容（目录输入、保存按钮）不再被转圈顶掉。
- **渲染**：供应商表单区块、模型列表行、MCP 服务器行 memo 化，键入不再重渲无关行。
