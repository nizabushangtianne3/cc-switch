# CC Switch v4.0.30

本リリースは、上流ゲートウェイがクライアント指紋でリクエストを丸ごと拒否してセッションが途切れる問題を修正します。

## 修正

### ゲートウェイがクライアント形態で丸ごし拒否するリクエストを標準クライアントで再送

一部のゲートウェイ（AMD 開発者サイトの前段の Azure Application Gateway など）は TLS/HTTP クライアントの指紋でリクエストを丸ごと拒否します。有用な情報を持たない HTML 400 を返し、同じバイト列でも標準クライアントなら通ります（同一マシンで実測：curl は成功、当方の標準クライアントも成功、拒否されたのはプロキシの2つの送信経路だけ）。クライアントはその 400 でセッションを中断し、以降同セッションのリクエストも全て失敗していました。

2つの送信経路（元の header 大文字小文字を保つ raw 経路と、OpenAI 系フォーマット（chat/completions・responses・Codex ネイティブ）が使る reqwest プール経路）にフォールバックを追加しました。ゲートウェイ拒否（4xx/5xx かつレスポンスが JSON 以外。本当の API エラーは JSON なので誤発動しません）を受け取ったとき、同じバイト列を標準クライアントで一度だけ再送します。クライアントが見るのは再送後のレスポンスで、セッションは途切れません。設定済みのプロキシは再送時に迂回しません。
