# CC Switch v4.0.18

### 4.0 稳定线的第 9 个修复版本

本版把 DeepSeek 的 DSML 清洗从“按模型名处理”改成统一的输出规则：只要 Chat 上游的响应里出现 DSML 工具调用脚手架，所有模型都会走同一套解析、剔除和还原逻辑；思考续写防护也不再要求模型名包含 DeepSeek。

## 改进

- **统一的内联工具调用规则。** 解析由响应文本本身驱动，不再检查模型名或供应商名。v4.1 的空格方言、标准 DSML 块、ASCII 竖线回退和 `<｜｜DSML｜｜:ToolName>` 形态都走同一条路径；完整块还原为真正的工具调用，孤立标记和 `_INVOKE_PREFIX = '` 这类解析器片段被剔除。
- **思考续写防护对所有模型生效。** 只要同一个响应里已经产出未结束的 reasoning，后续被上游错误放进 `content` 的长片段仍会留在思考通道，不再显示成正文。

## 升级说明

- 没有数据库结构变化，仍是 21。
- 不需要手动改配置；升级后重新发起对话即可生效。
- fork 的多 Key 池、按 Key 用量统计和单 Key 持久化行为不变。
