# CC Switch v4.0.29

This release merges upstream GitHub Copilot CLI support and fixes a problem that could ruin whole third-party sessions: when the upstream rejects unsupported parameters, the session is no longer lost.

---

## New

### GitHub Copilot CLI as a managed app

Copilot CLI (`copilot`) is now a managed app like Claude Code and Codex:

- **Official cards**: "Open terminal" launches with the GitHub account token bound in the Auth Center, plus the model and reasoning effort configured on the card; adding the card writes no files.
- **Bring-your-own-model cards**: the base URL, key and model are passed to this single `copilot` process through `COPILOT_PROVIDER_*` environment variables, so keys never land in a persistent file; a card counts as isolated only when it carries both the URL and credentials.
- **Sync**: MCP servers (`mcp-config.json`), Skills and the instructions file follow each card's app selection.
- **Sessions**: list, search and resume Copilot CLI sessions; import usage from session logs.
- **Deep links**: import Copilot providers from `ccswitch://` links.
- **Shell**: app list, card badges, connectivity check and the uninstall list all cover Copilot CLI.

## Fixes

### Unsupported parameters no longer kill the session

Third-party models vary widely in which request parameters they accept (`reasoning_effort`, `tool_choice`, `temperature`, ...). A generic request used to be rejected whole with a 400, the client aborted the session, and every later request in that session failed too. The proxy now absorbs it:

- **Parameter-stripping retry**: on a 400 that names the offending parameter, the proxy removes those keys from the request body and retries once against the same provider, so the client sees a 200 and the session continues. Only explicit wording is honored (OpenAI's `error.param`, `Unsupported parameter: 'x'`, `does not support the 'x' parameter`, `Unknown field x`, Chinese "不支持的参数", ...); when nothing can be parsed the rectifier gives up instead of guessing, and core keys (`model`/`messages`/`stream`/`input`) are never stripped.
- **Capability cache**: "this provider's model does not accept these parameters" is remembered in memory and persisted to settings, so it applies from the very first request after a restart; later requests (same session or new sessions) are stripped before being sent, with no error at all.
- The cache is visible and editable in Settings; clearing it restores the generic request shape.

## Improvements

- **Copilot / xAI auth**: the outer `RwLock` around the managers is gone (they already lock internally), so read locks no longer span upstream network round-trips and logins or account removals are no longer blocked by usage queries.
- **Lazy settings sections**: opening Settings loads only the default General section; each section's code is fetched on demand, and every lazy block shows its own loading state, so static content in the same section (directory inputs, save buttons) is no longer hidden by a spinner.
- **Rendering**: provider form blocks, model list rows and MCP server rows are memoized, so typing no longer re-renders unrelated rows.
