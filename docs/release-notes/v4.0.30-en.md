# CC Switch v4.0.30

This release fixes sessions being cut short when an upstream gateway rejects requests based on the client fingerprint.

## Fixes

### Requests rejected whole by a gateway now retry through the standard client

Some gateways (for example the Azure Application Gateway in front of AMD's developer site) reject requests based on the client's TLS/HTTP fingerprint, answering with an HTML 400 that carries no useful information, while the exact same bytes go through a standard client (verified on one machine: curl succeeds, our own standard client succeeds, only the proxy's two outbound client paths were rejected). The client aborted the session on that 400 and every later request in the same session failed too.

Both outbound paths now have a fallback: the raw path that preserves original header casing, and the pooled reqwest path used by OpenAI-style formats (chat/completions, responses, native Codex). When either gets a gateway-class rejection (4xx/5xx with a non-JSON body, real API errors are JSON and never trigger it), the same bytes are re-sent once through the standard client. The client sees the retried response and the session continues. A configured proxy is never bypassed for the retry.
