# CC Switch v4.0.11

### The sixth fix release for the 4.0 stable line

This release fixes one save-path issue: when a provider form saves a single API key, it now writes that key and its scheduling strategy into provider metadata instead of writing them only when there is more than one key. Newly added single-key providers therefore have stable key metadata for key-level usage attribution. This release contains no legacy-data backfill or migration compatibility logic; existing single-key providers must be saved again or their key re-added.

## Fixed

- **Single-key providers lacked key metadata.** The form previously persisted `meta.apiKeys` and `meta.apiKeyStrategy` only when there was more than one valid key. It now persists both when there is at least one. This does not enable multi-key routing and does not change provider retry behavior.

## Upgrade notes

- No database schema change.
- This release does not infer credentials from old configurations; single-key usage attribution applies only to providers saved again or re-added in this version.
