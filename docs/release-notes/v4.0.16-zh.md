# CC Switch v4.0.16

本版本把上游 v4.0.13 至 v4.0.15 的更新合入 fork：托盘从原生菜单换成玻璃面板，用量页的趋势图可以选柱形图或曲线面积图，用量「设置」页签把显示币种、侧栏「今日」和请求日志的列放到一起。同时修好了经路由的请求认不出 Claude Code 会话、Codex 连 DeepSeek 报 400、Windows 更新后设置被重置、WSL 里读不出 Hermes 会话等问题。fork 自己的多 Key 池、按 Key 的用量统计和单 Key 持久化都不变。

---

## 新增

**托盘改成玻璃面板。** macOS 和 Windows 上点托盘图标（左右键）弹出毛玻璃面板，不再挂原生菜单；常用操作和状态直接放在面板里。Linux（AppIndicator）不派发点击事件，保留原生菜单，并在菜单里放了一项打开面板。面板是独立的构建入口，也不参与窗口状态记忆。

**用量趋势图可以选柱形图或曲线面积图。** 柱形图是默认样式，两种样式的指标、坐标轴、悬停提示和币种换算一致；只有一个数据点时面积图会画一个点。

**Claude Desktop 可以为托管登录的供应商获取模型列表。** GitHub Copilot、Codex OAuth、xAI OAuth 这类供应商在 Desktop 表单里也有「获取模型列表」按钮，会按登录的账号拉取；没登录时先提示登录。

**Hermes 可以按模型声明支持图片输入。** 展开模型详情后有「支持图片输入」开关：打开写 `supports_vision: true`，关掉则删掉这个键，交给 Hermes 自己判断。

## 改进

**用量「设置」页签。** 原来的「定价」页签并入「设置」：上面是显示设置（显示币种与汇率、侧栏「今日」显示哪些项、请求日志显示哪些列），下面是模型定价。页签、预设时间范围和图表指标会记在本地，下次进用量页还原。

**侧栏「今日」只显示数值。** 可以选花费、Tokens、请求数、缓存命中率中的至多两项；一项也不选就整个不显示。完整说明放在悬停提示和读屏文本里。

**路由下切换供应商，提示写明实际做了什么。** 只有客户端配置文件真的改了，才提示重启。

**Windows 上卡片的「打开终端」带完整 PATH。** 不再因为应用内更新重启后缺少用户级 PATH 而报「'claude' 不是内部或外部命令」。

## 修复

- **经路由的请求认不出 Claude Code 的会话。** 新版 Claude Code 把会话 ID 写成 JSON 放在 `metadata.user_id` 里，以前解析不了，每个请求都被当成新会话；走 Codex OAuth 时没有稳定的缓存键，Claude Desktop 经路由连 Gemini 时工具调用报错。现在两种格式都认得，Claude Desktop 也读会话头。
- **Codex 经路由连 DeepSeek 报 400。** 回放工具历史时，工具调用和结果之间夹着的空消息、进度文字或思考内容会被拆成单独的消息。现在只对 DeepSeek 模型把它们并回工具调用那条消息。
- **Windows 更新后设置被重置为默认值。** 现在保存先写临时文件再替换，读取会去 BOM、有尾巴时只读第一段 JSON；没有完整读出的文件先备份成 `settings.json.broken-<时间>.bak`。
- **更新 Codex 时误卸载。** 只有 `--version` 真的运行并报错时才走先卸载再重装，其余情况照常升级。
- **WebDAV / S3 慢速传输到 300 秒被掐断。** 总超时现在随文件大小放宽，下载另设 120 秒无数据超时。
- **Windows 上读不出 WSL 里 Hermes 的会话。** 改为在对应的发行版内只读读取数据库（需要发行版里有 `python3` 3.7 及以上）。
- **供应商卡片拖拽时被拉长、互相重叠。** 拖动的卡片保持尺寸，移动锁定在纵向。
- **Skills 仓库的下载错误被「仓库或分支不存在」掩盖。** 现在只有 404 才回落到 `main` / `master`，超时、包过大、解压失败都会原样报出来。
- **故障转移后「路由中」标记还停在原来那家。** `provider-switched` 现在让整组供应商查询失效。

### 升级说明

- **数据库结构没有变化**（仍是 21）。
- Windows 上已经带着尾巴的 `settings.json` 会在首次启动时被恢复，原文件保留为 `settings.json.broken-<时间>.bak`；已经被此前的更新重置过的设置不会自动还原。
- Linux 上原生托盘菜单保留，macOS / Windows 改为托盘面板。
- fork 的多 Key 池、按 Key 的用量统计、单 Key 持久化行为不变；只加了一个 Key 的供应商仍需重新保存一次才能参与按 Key 的统计。
