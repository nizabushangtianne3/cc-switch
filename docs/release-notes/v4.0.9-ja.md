# CC Switch v4.0.9

### fork の正式署名付き Android リリース

このリリースでは、CC Switch が Android で利用できるようになります。正式署名済みの arm64 と armv7 の APK を用意し、Android アプリは既存の集約モードを再利用して、ローカルプロキシーによる統一ルーティングとキープール転送を続けます。使用量統計にもキー単位が加わり、アプリ・プロバイダー・モデル・キーで絞り込めます。リリースワークフローはアップロード前に Android 署名を検証し、fork 専用の Tauri 更新鍵でデスクトップ更新マニフェストを生成します。デスクトップでは Windows MSI、Linux AppImage / deb / rpm、macOS Universal DMG を引き続き提供します。fork リポジトリにはコード署名証明書がないため、デスクトップパッケージは未署名のままです。

---

## 新機能

**正式署名付き Android インストーラー。** Release Assets に 64 ビット用の `arm64-v8a` と 32 ビット用の `armeabi-v7a` の APK を同梱します。APK は GitHub Secrets に保存した release keystore で署名し、`versionCode` は `4000009` です。

**キー単位の使用量統計。** プロキシーリクエストは選択されたキーの SHA-256 フィンガープリントを保存し、生のキーは保存しません。使用量ページにキータブを追加し、アプリ・プロバイダー・モデル・キーで絞り込んでリクエスト数、トークン、コスト、成功率、遅延、速度を確認できます。現在のキーは `キー #番号 · マスク`、削除済みキーはフィンガープリントの先頭 8 桁で表示します。

## 改善

**Android での統一ルーティング。** Android アプリは集約モードのローカルプロキシーを再利用します。プロバイダー、モデルマッピング、複数キーのルーティングはデスクトップと同じバックエンド実装を使い、Agent ごとのプロキシー適応は不要です。

**リリース時の署名検証。** GitHub Actions は Android ビルド後に `apksigner verify` で各 APK を検証し、デスクトップ更新成果物と `latest.json` に署名します。署名用 Secret またはプラットフォーム署名が不足すれば失敗します。

## 修正

**Windows からの Android クロスビルド失敗。** 以前の `build.rs` は Windows manifest のリンカー引数をホスト側の cfg で判断していたため、Windows 上で Android をコンパイルすると `/MANIFEST` 引数が Android Clang に渡されていました。現在は `CARGO_CFG_TARGET_OS` を参照します。

## アップグレードに関する注意

**データベース構造は 21 にアップグレードされます。** 明細ログと 30 日後のロールアップに `api_key_id` フィンガープリント次元を追加します。アップグレード前に自動バックアップを作成します。古い行から使用されたキーを推定できず、キー統計では未識別として表示されるか除外されます。
