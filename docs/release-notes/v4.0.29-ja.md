# CC Switch v4.0.29

このリリースでは GitHub Copilot CLI 対応（アップストリームの取り込み）を含み、サードパーティモデルのセッション全体が使えなくなる問題を修正しました。上限が対応しないパラメータを拒否しても、セッションは途切れません。

---

## 新機能

### GitHub Copilot CLI を管理対象アプリとして追加

Copilot CLI（`copilot`）が Claude Code、Codex と同じ管理対象アプリになりました：

- **公式カード**：「ターミナルを開く」で認証センターに紐づけた GitHub アカウントのトークン（カードに設定したモデルと推論 effort も）を渡して起動します。カードの追加時にファイルは書きません。
- **自有モデル（BYOK）カード**：アドレス・キー・モデルは `COPILOT_PROVIDER_*` 環境変数でこの一度の `copilot` プロセスにだけ渡され、キーはファイルに残りません。アドレスと資格情報の両方が入ったカードだけが隔離起動とみなされます。
- **同期**：MCP サーバー（`mcp-config.json`）、Skills、手順ファイルがカードのアプリ選択に従って同期されます。
- **セッション**：Copilot CLI のセッション一覧・検索・再開、セッションログからの使用量取り込みに対応。
- **ディープリンク**：`ccswitch://` リンクから Copilot プロバイダーを読み込み。
- **シェル**：アプリ一覧、カードのバッジ、接続検査、アンインストール一覧も Copilot CLI に対応。

## 修正

### 未対応パラメータの拒否でセッションが全部使えなくなる問題

サードパーティモデルが受け付けるリクエストパラメータにはばらつきがあります（`reasoning_effort`、`tool_choice`、`temperature` など）。従来は汎用形態のリクエストが 400 で丸ごと拒否され、クライアントはセッションを中断、以降そのセッションのリクエストも全て失敗していました。プロキシ層で吸収するようにしました：

- **パラメータ削除リトライ**：拒否されたパラメータを名指しする 400 を受けたら、リクエストボディからそのキーを削除して同一プロバイダーに一度だけリトライします。クライアントが見るのは 200 で、セッションは途切れません。明示的に名前を挙げる表現だけを尊重し（OpenAI の `error.param`、`Unsupported parameter: 'x'`、`does not support the 'x' parameter`、`Unknown field x`、中国語の「不支持的参数」など）、解析できない場合は推測せず諦めます。`model`/`messages`/`stream`/`input` などのコアキーは絶対に削除しません。
- **能力キャッシュ**：「このプロバイダーのこのモデルはこれらのパラメータを受け付けない」をメモリと settings に永続化します。再起動後の最初のリクエストから効き、以降のリクエスト（同じセッションでも新規セッションでも）は送信前に剥がされるため、エラーは一切出ません。
- キャッシュは設定で確認・編集でき、削除すると汎用形態の送信に戻ります。

## 改善

- **Copilot / xAI 認証**：マネージャーを包む外側の `RwLock` を廃止（内部には細粒度ロックがある）し、読み取りロックが上流のネットワークラウンドトリップを跨ぐことがなくなりました。ログインやアカウント削除が使用量クエリでブロックされません。
- **設定の遅延読み込み**：設定を開くと既定の「一般」セクションだけを読み込み、切り替えたセクションのコードをその都度取得。各遅延ブロックが独自の読み込み中表示を持ち、同じセクション内の静的コンテンツ（ディレクトリ入力、保存ボタン）がスピナーで隠れません。
- **描画**：プロバイダーフォームのブロック、モデル一覧の行、MCP サーバー行をメモ化。入力しても無関係な行は再描画されません。
