# CC Switch v4.0.32

## 修正

### スト内 error イベントでも剥離リトライ

Anthropic 系の上流が変換時に注入したパラメータを拒否するときの応答は HTTP 200 + ストリーム先頭の error イベントで、イベントには構造化された param フィールドがなく、パラメータ名が措辞の前に出てきます（`"thinking" is not supported for this model...`）。前版は「措辞の後ろの単語」と構造化フィールドだけを認識していたため、この形態は整流できず、クライアントはスト内エラーでセッションを中断していました。構造化フィールドも措辞パターンも取得できない場合、引用符で囲まれた正当なパラメータ名を収集するフォールバックを追加しました。誤収を防ぐ2つのゲートがあります（JSON エラー信封のみ、かつ「非対応」と明記するメッセージのみ）。Codex の署名診断（signature と thinking をバッククォートで囲んだあのメッセージ）は影響を受けず、署名整流のままです。

### テストがユーザー設定を汚染しない

能力キャッシュのテストが実際の settings.json を直接読み書きしていたため、テスト実行でテスト用エントリがユーザー設定に書き込まれ、次回起動時にウォームアップされることがありました。一時ホームに分離し、opencode テストと他モジュールが互いの一時ホームを壊す競合も修正しました。
